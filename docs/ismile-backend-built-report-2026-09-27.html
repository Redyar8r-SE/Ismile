Safety rules the code enforces

  • No ticket without money confirmed by Psoola. The browser can never say "paid". Our server asks Psoola directly and checks the amount and currency.
  • The server sets the price from the admin, never the page. A price of 0 cannot be paid.
  • Paid twice? Only one ticket is made. The second payment is flagged red for Finance to refund.
  • Admin: each person has their own account and role. There is a phone code (two-factor) for Owner and Finance. Five wrong passwords lock the account for 15 minutes. Every action is written to the audit log.
  • Student ID photos are stored outside the website, shown only to signed-in staff, and deleted after the summit.
  • Test mode: until launch every email goes to one test address, so no real person gets a test ticket.

5Security review

A second, independent check read all the new code looking for ways to break it. It confirmed that the main safety rules hold. It found 6 real problems, and all 6 are now fixed, each with a new automatic check that proves it.

#Problem foundNow
1After signing in, a trick link could send an admin to a fake website.fixed
2If a card was declined and the person then paid on the same Psoola page, the money could be taken with no ticket.fixed: ticket made
3A link that kept failing (Psoola down) could send "Pay now" emails again and again.fixed: max 1 a day
4Switching registration off did not stop "Pay now" links.fixed: stops all payments
5Many people paying for the last few places at the same moment could oversell tickets or lunch.fixed: places held while paying
6A rejected student could be approved before sending a new photo.fixed
+Also fixed: the pretend Psoola can never run on the real address, even if a setting is copied wrongly. Odd links no longer cause error pages, and very large photos are refused.fixed
