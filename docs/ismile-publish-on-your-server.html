3What changes the day we publish, and what does not

Better at once

  • Address https://ismile.krd with the padlock
  • Admin Save is instant (today it takes 1–2 minutes)
  • No GitHub key in the browser; a real server sign-in
  • Emails on your own name: info@ismile.krd
  • Daily backups
  • A test site for trying changes safely

Still the same until the backend is built

  • Registrations are not saved yet
  • No payments through Psoola yet
  • No ticket emails yet
  • Sponsor requests still go by WhatsApp / email
  • Workshops still by phone
Important before publishing: the registration form today says "You're registered!" but saves nothing. On the new address, switch the registration page to "Registration opens soon" (or to sending the details by WhatsApp) until the backend is ready, so nobody thinks they have a ticket.

4The publishing route at a glance

In total about 2–3 days, most of it waiting for the domain to connect. The website is not down at any point: GitHub Pages keeps working until the new address is ready.

A

Buy You

  1. Ask the host's chat the 3 questions: cron every minute? outgoing HTTPS from PHP? daily backups for how many days?
  2. Buy the cPanel hosting on a yearly plan (see the server guide for examples).
  3. Buy ismile.krd for 2+ years from a .krd seller, in the organiser's name, with auto-renew on.
  4. Turn on 2-step login for cPanel. Create a separate login for the developer; never share your own password.
Done when: you can log in to cPanel and you own ismile.krd.

5Publishing, step by step

B

Connect the domain to the hosting You + the host's chat

  1. The host gives you two nameservers (e.g. ns1.host.com, ns2.host.com); they are in the welcome email.
  2. At the domain seller, replace the domain's nameservers with those two.
  3. Wait. It usually works in a few hours, sometimes up to 48 hours.
  4. In cPanel → SSL/TLS Status → Run AutoSSL. The padlock appears.
Done when: https://ismile.krd opens (an empty "welcome" page is fine) with the padlock.
C

Upload the website Developer

Two ways; Git is better because updates later are one click.

  1. Git way: cPanel → Git Version Control → Create → clone github.com/Redyar8r-SE/Ismile into a folder outside public_html; a small .cpanel.yml file then copies only the website folders listed below into public_html.
    Or simple way: download the project as ZIP from GitHub → cPanel → File Manager → public_html → Upload → Extract.
  2. Upload these: index.html register.html workshops.html sponsor.html admin.html favicon.ico and the folders css/ js/ data/ assets/ server/.
  3. Do not put docs/ on the public site: it has the internal plans and Psoola questions. netlify/ and tools/ are not needed there either.
  4. cPanel → MultiPHP Manager: choose PHP 8.3 for ismile.krd.
Done when: https://ismile.krd shows the iSmile home page, in all three languages, on a phone and a laptop.
D

Switch on admin saving on the server Developer

  1. In server/, copy admin-config.sample.php to admin-config.php.
  2. Fill in secret (a long random line) and one account per person: email + password hash. Make the hash on a computer with Node.js:
node -e "const c=require('crypto'),s=c.randomBytes(16);console.log('pbkdf2$150000$'+s.toString('base64')+'$'+c.pbkdf2Sync('your-password',s,150000,32,'sha256').toString('base64'))"
  1. Keep the hash in single quotes in the file (it contains $ signs).
  2. Put { "api": "/server/admin.php" } in data/admin-server.json.
  3. Make sure data/ and assets/uploads/ can be written by PHP (File Manager → Permissions, usually 755).
  4. Test: open https://ismile.krd/admin.html → sign in → change one word → Save → reload the home page. The word has changed at once.
Done when: a save shows on the site immediately. If it says "Please sign in again", the server/.htaccess file is missing; upload it (it is hidden: turn on "show hidden files").
E

Email addresses Developer + you

  1. cPanel → Email Accounts → create info@ismile.krd, sponsors@ismile.krd; tickets@ismile.krd will be used for ticket emails later.
  2. Open them on your phone (the host shows the settings) or forward them to an address you already read.
  3. In the admin, set "Where sponsor requests go" to sponsors@ismile.krd if you want.
Done when: an email sent to info@ismile.krd arrives on your phone.
F

Test site Developer

  1. cPanel → Domains → create test.ismile.krd in its own folder.
  2. cPanel → Directory Privacy → lock that folder with a password.
  3. Put the same website there. From now on every change is tried here first.
Done when: test.ismile.krd asks for a password and then shows the site.
G

The old address and the old saving method Developer

  1. Replace the GitHub Pages site with a small page that forwards visitors to https://ismile.krd, or switch GitHub Pages off once the new address is announced.
  2. In the admin press Sign out to remove the GitHub key from the browser, then delete that key on github.com (Settings → Developer settings → tokens).
  3. Switch off the Netlify site; it is not needed any more.
  4. Remove the browser-only password lock of the admin; the server sign-in replaces it.
Done when: the old address lands on ismile.krd, and no GitHub key exists any more.
